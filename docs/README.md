# SmartNote 文档索引

仓库里的文档分三类：**用户看的**、**验收用的**、**维护用的**。改完代码先看下面的「改了什么 → 要同步哪里」，再跑一次一致性检查。

---

## 一、文档清单

| 文件 | 面向谁 | 内容 | 能不能手改 |
|---|---|---|---|
| `README.md` | 用户 | 安装、功能总览、注意事项、反馈 | 手写 |
| `docs/功能清单.md` | 验收的人 / AI | 逐项验收表：入口、操作、预期结果 + 已知边界 + 构建命令 | 手写 |
| `docs/notes.md` | 维护的人 / AI | 实施笔记：实际做了什么、留了什么、为什么 | 手写 |
| `docs/代码地图.md` | 维护的人 / AI | `Sources/` 全文件清单：行数、主要类型、一句话说明 | **脚本生成** |
| `docs/文案清单.md` | 维护的人 / AI | 全部中文文案清单（用户可见 / 内部日志分开），含重复与可疑项 | **脚本生成** |
| `docs/设置项清单.md` | 维护的人 / AI | `AppSettings` 字段表：默认值 + 六个落点覆盖 + 视图引用 | **脚本生成** |

三份生成物由 `scripts/check-docs.py` 产出，**不要手动编辑**：手的改动会在下次检查时被判为"过期"。要改内容就改代码，然后重新生成。

---

## 二、改了什么 → 要同步哪里

| 你改了什么 | 必须同步 |
|---|---|
| 侧栏增加/删除/改名一项 | `ContentView` 的 `DetailView` case；`docs/功能清单.md`（项数与验收项）；`docs/notes.md` 对应章节 |
| 新增设置项 | `AppSettings` **六处**（属性 / `==` / `CodingKeys` / `init()` / `init(from:)` / `encode(to:)`）；设置页 UI；`docs/设置项清单.md`（重跑生成） |
| 新增数据文件 | `StorageService.ManagedDataPath`（否则不进备份、清不掉）；`docs/notes.md` |
| 改数据 schema | `schemaVersion` + 迁移逻辑；`docs/功能清单.md` 第 9 章（备份与数据安全） |
| 新增 Siri / Shortcuts 短语 | `docs/notes.md` 第 17 章；`README.md` 短语数量 |
| 改主题 / 背景图 | `AppTheme`；`README.md` 的主题方括号列表 |
| 改版本号 | `project.yml` 的 `MARKETING_VERSION`；`README.md`；归档命令里的版本 |
| 用户可见文案 | `docs/文案清单.md`（重跑生成）；注意别把开发编号写进界面 |

## 三、一致性检查

```bash
python3 scripts/check-docs.py        # 检查，硬错误退出码 1；输出带 file:line 证据
python3 scripts/check-docs.py gen    # 重新生成上面三份自动文档
python3 scripts/check-docs.py --list # 列出检查分组
bash scripts/self-test-check-docs.sh # 自测：确认检查器真的会拦（8 个负向用例）
```

只依赖 Python 标准库，不需要联网、不需要装包。

检查分五组：

| 组 | 检查什么 | 例子 |
|---|---|---|
| A 数字一致性 | 文档里写死的数字/名单 vs 代码与资源的真值 | 侧栏项数、Siri 短语数、答案条数与构成、主题名单、数据文件名、文档里的仓库内路径是否存在 |
| B 结构一致性 | 跨文件的结构对应关系 | 侧栏 tab ↔ `DetailView` case 一一对应；`AppSettings` 31 个字段在四个落点全覆盖（缺一个就是"改了设置不生效"或"重启归零"） |
| C 生成物新鲜度 | 三份自动文档是否与当前代码同步 | 改了代码不重新生成 → 直接算硬错误 |
| D 章节编号 | `notes.md` 章节号不重复、不倒序 | 曾经出现 `…22, 24, 23…` 的倒序，已修正 |
| E 覆盖与文案 | 每个侧栏入口都有验收项；中文文案里的可疑模式 | 新增侧栏项却没写验收项；疑似开发编号、占位符、标点混用 |

## 四、自测：证明检查器真的会拦

一个"永远打印 ✓"的检查器和没有检查器是一样的。所以仓库里还有一份负向自测：

```bash
bash scripts/self-test-check-docs.sh
```

它故意制造 8 种"文档变假话"的情形（文档数字改错、改了代码没重新生成、主题改名文档没跟、侧栏入口没接详情页、新增设置项漏改六处之一、文档指向已删除文件、章节号重复、侧栏入口没写验收项），每种都要求检查器报硬错误并退出码非 0，跑完自动 `git checkout` 还原。**改动 `check-docs.py` 的检查逻辑后应当跑一遍**，否则你不确定它还在拦。

自测会先检查它要触碰的文件有没有未提交改动，有就拒绝运行（退出码 2），不会覆盖你正在写的代码。

## 五、可选：提交前自动检查

仓库自带 `scripts/hooks/pre-commit`，但它需要手动挂上（`.git/hooks/` 不随仓库分发）：

```bash
ln -sf ../../scripts/hooks/pre-commit .git/hooks/pre-commit
```

挂上之后每次 `git commit` 会先跑一遍检查，不一致就中止提交。不想被拦就跳过这一步，改成手动跑。
